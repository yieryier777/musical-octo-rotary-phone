大模型的上下文（Context）

一句话定位：模型一次推理所能"看见"的全部信息——系统提示、对话历史、工具结果、检索资料的总和；模型本身无状态，上下文就是它此刻的全部世界。

核心问题

  • 模型明明"没有记忆"，为什么用起来好像记得上一句话？
  • 上下文窗口装不下时，系统会怎么办？
  • 上下文里的知识和模型训练学到的知识有什么区别？
  • 为什么把资料放在上下文中间，效果反而会变差？

我的解释

我把大模型理解成一台"失忆阅读机"：每次生成回答之前，它把窗口里的所有文字从头到尾重新读一遍，然后接着往下写。

它"记得"我上一句话，不是因为它有记忆，而是因为那句话被完整地塞进了这一次的输入里。所以上下文就是模型的临时笔记本：你往上面写什么，决定它此刻知道什么；合上本子（会话结束、或历史被截断），一切归零。

这个理解带来一个实用推论：想让模型表现更好，与其纠结"哪个模型更聪明"，不如先学会"该给它看什么、按什么顺序看"——这正是"上下文工程"要解决的问题。

2. 三个关键机制

机制含义出处
注意力机制Transformer 生成每个 token 时都可以"回看"窗口内的所有 token，据此计算关联权重——这是上下文能被整体利用的技术基础。《Attention Is All You Need》
窗口有限性窗口以 token 计数且有上限（从几千到上百万不等）。超限时系统必须截断、压缩摘要或只保留检索相关的片段；按 token 计费也意味着上下文越大越贵。Anthropic 上下文工程实践
位置敏感性"Lost in the Middle"：模型对开头和结尾的信息利用最好，放在窗口中间的关键信息容易被忽略——资料的位置本身就是工程质量问题。Liu et al., 2023

3. "记忆"的真相

模型每次调用都是独立的：所谓多轮对话，是客户端把历史消息每次都重新发给模型。跨会话的"长期记忆"则依赖外部方案——把重要信息写入文件或数据库，下次再检索出来放进上下文（例如项目里的记忆文件、RAG 知识库）。

具体应用场景

场景：本次作业的生成过程（2026 年 9 月，WorkBuddy）。

我让 WorkBuddy 完成作业时，它的上下文里同时装着：系统提示、我粘贴的完整作业要求、它读入的 SKILL.md 内容、以及每一次执行命令返回的结果（git 版本号、克隆失败的报错、curl 测试各域名的输出）。

当它"记得"github.com 连不上时，并不是它有什么记忆——是那次连接失败的报错文本还留在上下文里，支撑它后续选择改走 API 通道。反过来，如果对话轮次太多，早期的作业要求细节可能被压缩或挤掉，它就会"忘记"某些要求——这时最好的办法是新开会话或重发关键信息，而不是责怪它"记性差"。

概念辨析与使用边界

易混淆点辨析
上下文 vs 训练知识训练知识固化在模型参数里、无法更新（模型不知道训练截止日期之后的事）；上下文是"这一次给它看的"，即时生效。让模型用新资料，靠的是放进上下文，不是它"学过"。
上下文 vs 聊天记录界面上的聊天记录是客户端保存的展示层；每次请求仍然要把相关历史重新发给模型。清空界面 ≠ 模型失忆，发新请求不带历史才等于失忆。
窗口大 ≠ 效果好塞入过多内容会引入位置偏差（中间信息失效）、成本与延迟上升、无关信息稀释注意力。上下文工程追求"最少且足够的正确信息"。
RAG / 记忆文件 / Skill 的共同本质三者都不是在"改变模型"，而是不同策略的"往上下文里放东西"：RAG 放检索到的资料，记忆文件放历史要点，Skill 放任务方法。

使用边界与注意事项

  • 不要把敏感信息贴进上下文：密码、API Key 一旦进入对话，就可能被存储或泄露（本作业的 .gitignore 也因此排除了相关文件）；
  • 超长任务要主动管理：分段、摘要、关键信息前置（放在开头或结尾而非中间）；
  • 指望"全塞进去"常常失效：与其粘贴整本书，不如先检索出相关章节。

1. 以下哪一项通常不在模型单次推理的上下文窗口里？

✔ 正确答案：D。上下文 = 系统提示 + 指令/Skill 注入 + 对话历史 + 工具结果 + 检索资料 + 当前输入。模型不会"顺带"知道窗口之外的任何事——一切"知道"都必须以 token 的形式出现在上下文里。

2. 为什么说"模型没有记忆"，但用起来好像记得上一句话？

✔ 正确答案：B。模型每次调用是无状态的；"记得"是因为那句话被完整地塞进了这一次的输入。界面上的聊天记录只是展示层——新请求不带历史，才等于"失忆"。

3. "Lost in the Middle" 现象指的是？

✔ 正确答案：B。这是 Liu et al.（2023）的实验发现。对写提示词的启示：把最重要的指令和资料放在开头或结尾，不要埋在长文本中间。

4. 下列哪一项属于"把知识放进上下文"，而不是"把知识写进模型"？

✔ 正确答案：B。RAG、记忆文件、Skill 的共同本质都是"往上下文里放东西"，即时生效、不改变模型本身；微调、继续预训练、蒸馏则会修改模型参数。这是"使用上下文"与"训练模型"的分水岭。
