Agent（AI 智能体）

一句话定位：以大模型为决策核心，能自主调用工具，通过"感知—思考—行动"循环一步步完成目标的 AI 系统。

  • 大模型已经是"大脑"了，为什么还需要其他组成部分？

  • 什么情况下不该用 Agent？

我的解释

我把 Agent 理解成"给大模型装上手脚和目标，让它自己干到底"。

平时我向 ChatGPT 这类助手提问，模型的职责只是"回答这一次"；而 Agent 是把模型放进一个循环里：它先读当前状况（上下文）→ 决定下一步做什么（继续思考、调用工具，还是宣告完成）→ 执行 → 看结果 → 再决定下一步。就像"顾问"和"实习生"的区别：顾问给建议，实习生拿着真实权限去改文件、提交代码、发邮件，而且自己判断做没做完。

所以 Agent 的关键不在"更聪明"，而在"有行动能力 + 有循环 + 有停止判断"。

核心机制与组成

综合 Anthropic 的工程实践与 Lilian Weng 的经典框架，一个 Agent 通常由以下部分构成：

组成部分作用类比
大模型（LLM）决策核心：读取上下文，产出下一步决策（文本回复或工具调用指令）大脑
工具（Tools）文件读写、执行命令、联网搜索、调用 API——让模型能作用于真实世界手
上下文（Context）系统提示、任务历史、工具返回结果，构成模型每轮决策的"全部已知信息"工作记忆
循环（Agent Loop）思考与行动交替进行（ReAct 模式：Reason → Act → Observe），直到模型判断任务完成干活的节奏
护栏（Guardrails）权限范围、敏感操作确认、步数与资源限制，防止误操作失控安全带

ReAct 论文将这一过程形式化为"推理（Reason）"与"行动（Act）"的交替：模型先写出"我需要先查一下……"的思考，再发起行动，行动结果作为新的观察进入下一轮推理。

具体应用场景

场景：本次作业的完成过程（2026 年 9 月，WorkBuddy）。

我在 WorkBuddy 中发出指令："帮我完成这份作业：建 GitHub 仓库、写 Skill、生成学习资料并推送。"接下来的半小时里，AI 作为 Agent 自主完成了一长串步骤：

  1. 感知：读取作业要求与当前对话上下文；
  2. 思考：规划出"检查环境 → 建仓库 → 写文件 → 提交推送"的路径；
  3. 行动：调用命令行工具检查 git 和 gh 的安装情况；
  4. 观察：发现 gh 未安装、github.com 无法直连（连接被重置）；
  5. 再思考、再行动：改变策略，改用可以连通的 GitHub API 通道；
  6. 循环继续：创建目录、写入文件、执行 git commit，并在每个关键节点向我确认。

我事先没有告诉它"如果 github.com 连不上该怎么办"——这条应对路径是它根据观察结果自己规划的。这正是 Agent 与固定脚本的区别：路径不确定时，由模型动态决策。

概念辨析与使用边界

易混淆概念与 Agent 的区别
Chatbot（对话助手）只负责"回答"，不作用于外部世界；没有工具调用，也没有自主的多步循环。多轮对话 ≠ Agent。
Workflow（工作流）Anthropic 的划分标准是"流程由谁决定"：Workflow 中每一步由人预先写好的代码编排，LLM 只是流程中的执行单元；Agent 中步骤由模型自己动态决定。
自动化脚本 / RPA规则完全固定，遇到没预设过的情况就失败；Agent 依靠模型的泛化能力应对变化的情形。
单次工具调用很多产品宣传的"Agentic 功能"其实只调一次工具就返回，没有"观察—再决策"的循环，只能算增强版的问答。

使用边界（什么时候不该用 Agent）

  • 高确定性、低容错的重复任务：固定脚本或 Workflow 更稳定、更便宜、更快；
  • 成本与延迟敏感：Agent 循环的每一轮都要消耗 token，步数不可预先估计；
  • 错误会累积：多步自主行动中，早期小错可能被放大，重要操作（删除、支付、发布）必须有护栏与人工确认。

1. Agent 与 Chatbot 最本质的区别是什么？

✔ 正确答案：B。Chatbot 的职责只是"回答这一次"，生成文本就结束；Agent 把模型放进循环里——有工具（行动能力）、有"观察—再决策"、有停止判断。区别不在模型强弱，而在"能行动 + 有循环 + 会判断何时结束"。

2. 某系统用代码预先写死了流程（第一步做什么、第二步做什么都由人编排），只是每一步内部调用了大模型。它属于 Workflow 还是 Agent？

✔ 正确答案：B。Anthropic 给出的划分标准是"流程由谁决定"：由代码预先编排 = Workflow，大模型只是流程中的执行单元；由模型根据观察动态决定下一步 = Agent。

3. Agent 循环中"观察"（Observation）这一步的输出去向是？

✔ 正确答案：B。工具执行结果被写回上下文，成为模型下一轮"感知"的内容——这正是上下文作为"工作记忆"的角色。模型的参数在推理过程中不会改变。

4. 下列哪个场景最适合用 Agent，而不是固定脚本或 Workflow？

✔ 正确答案：C。高确定性、低容错的重复任务（A/B/D）用脚本更稳定、更便宜、零 token 成本；Agent 的价值在于路径不确定时由模型动态决策——正如本资料应用场景中"发现 github.com 连不通后自主改走 API 通道"的情形。
